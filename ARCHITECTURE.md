# Architecture

## Layers

Each crate depends only on the crates below it.

- `brain-report`: the names brain counts its own use by (kinds of event and the door they came through), and later the usage report's types, signing and checking. No I/O, so the usage Worker builds it for wasm too.
- `brain-platform`: everything that touches the operating system. Folders, atomic and private file writes, moves that refuse links, archiving instead of deleting, and the clock. Platform-specific code lives here and nowhere else.
- `brain-note`: one note. Frontmatter that round-trips byte for byte, the one function that decides what a note may disclose, ids, wikilinks, the vault walk and the promote gate.
- `brain-index`: the SQLite index beside each person's data, embeddings and hybrid search. The index is a cache: it can always be rebuilt from the vault. It belongs to one vault: a reindex over another drops every row first, and a reader refuses to answer from another vault's rows. Beside it, `activity.db` holds what the vault cannot give back: counts of brain's use per day, kind and door, and the gaps (questions no note answered, with their text, which stays on the machine). It is not a cache, so it is never deleted or rebuilt with the index. Both open through `db::open`, the one place a database connection opens; opening an up-to-date database only reads, so a reader never waits on the daemon's writes. Whether a search found an answer is decided once, by `is_gap`: with vectors, the closest note below `GAP_FLOOR` is a gap whatever words matched; without vectors, no matching word is.
- `brain-reflex`: the reflex engine. It runs the reflexes at a hook point, writes each verdict to `verdicts.db`, and records every run in `traces.db` with the published `omit-agent-trace` crate. A reflex reads the outside only through its `Cx`, so a recorded run replays with nothing read again. Every reflex ships in shadow. Beside the reflexes, a hook point can have standing context, which judges nothing and is traced the same way: a session starts with the notes due for review and the memory indexes the person named. See `docs/traces.md`.
- `brain`: the binary. The CLI, the learning-loop import, the inbox, updates, the daemon, the MCP server and `brain hook`, which answers Claude Code's hooks inside 250 ms and always exits 0.
- `brain-usage`: omit's usage endpoint, a Cloudflare Worker. Its library turns a report `brain_report::accept` took into upserts of counts, tested natively on SQLite; its `shell` module, compiled only for `target_arch = "wasm32"`, is the Worker around them over D1. `target_arch` names a build target, not an operating system, so this cfg is not platform code and the rule that keeps platform cfg in `brain-platform` does not bar it. CI's `wasm` job is the only lint and build that sees the shell.

`brain-repo-rules` holds no code. Its tests read the repository itself and fail when a repo rule breaks.

## Processes

One process writes the index: whoever holds `writer.lock` in the data folder, which the operating system frees when that process dies, however it dies. `brain daemon` holds it for as long as it runs, watches the vault, and after any change that can matter (a `.md` path, or any creation, rename or removal, never anything inside a hidden folder) brings the index up to date, then embeds one batch at a time, newest notes first, so a save is never stuck behind a long first embed. A note rewritten with the same title, tags and body keeps its vector. After a pass that changed notes, once nothing is waiting for a vector and at most once an hour, it searches the open gaps again, newest first, on a thread of its own with its own read of the index, so a save is never behind them. It writes no id into a note saved in the last five seconds, so a note being typed is left alone until its owner stops, and a full pass every ten minutes catches whatever the watcher missed. A vault folder that is gone fails the pass and leaves the index as it was; the pass is tried again six seconds later, with the watch set up again. `brain index` and `brain import` take the lock when it is free and otherwise leave indexing to the daemon; the import writes each copy's id itself, so its copies are final with or without an index. The CLI, and later the MCP server and the hooks, only read the index; `brain status` says whether a daemon runs by a shared probe that never blocks a writer.

`brain memory follow` makes the memory import repeat: the daemon looks at the followed folder every minute (`import::sync`). `import.lock` is held from the ledger's read to its last save by every command that writes it. A copy is archived only when its ledger entry names the followed folder, its bytes are what brain wrote and two looks in a row found its source not there.

## Platforms

CI builds and tests every push on macOS, Linux and Windows, on GitHub-hosted runners only. A test that means something only on Unix (file modes) asserts the Unix fact under `cfg(unix)` and the Windows fact under `cfg(windows)` inside `brain-platform`'s tests; neither is skipped. `.gitattributes` fixes LF line ends everywhere, so byte-compared files mean the same on every platform. Every job stages ONNX Runtime from NuGet with `scripts/fetch-ort.sh` and sets `ORT_DYLIB_PATH`, because GitHub's copy has been gone since November 2026.

`brain start` and `brain stop` run the daemon as a launchd agent, so they work on macOS only in Phase 1; on Linux and Windows they say so, `brain daemon` runs by hand, and an update finds no agent to restart. Their launchd tests run on macOS only, against a `launchctl` stub named by `BRAIN_LAUNCHCTL`; `start_outside_macos_says_so` runs on the other two.
